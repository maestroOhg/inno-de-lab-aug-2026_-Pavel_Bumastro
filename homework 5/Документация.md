Документация

1. Описание бизнес-процесса и уровня детализации (Grain)
	Предметная область: Управление фитнес-клубом

	Бизнес-процесс: Продажа абонементов и клубных карт клиентам. Данный бизнес-процесс фиксирует финансовые транзакции приобретения 	или 	продления абонементов различных категорий

2. Уровень детализации (Grain): Одна строка в таблице фактов соответствует одной транзакции продажи одного абонемента конкретному 	клиенту в конкретный календарный день

3. Определение таблиц измерений (Dimension Tables)

	dim_client (Клиент):
	Содержит атрибуты клиентов
	client_sk (BIGINT, Primary Key) — суррогатный ключ хранилища
	client_id (INT) — бизнес-ключ
	full_name (VARCHAR) — ФИО клиента
	gender (VARCHAR) — пол клиента
	birth_date (DATE) — возраст клиента

	dim_season_ticket_type (Тип абонемента):
	Классифицирует продаваемые номенклатурные позиции
	ticket_type_sk (BIGINT, Primary Key) — суррогатный ключ хранилища
	ticket_type_id (INT) — бизнес-ключ
	name_ticket_type (VARCHAR) — название типа абонемента
	category (VARCHAR) — категория (безлимитный, дневной, разовый и т.д.)
	
	dim_date (Дата):
	date_sk (INT, Primary Key) — суррогатный ключ формата YYYYMMDD
	full_date (DATE) — календарная дата
	day (SMALLINT) — день месяца
	month (SMALLINT) — номер месяца
	year (SMALLINT) — год
	week (SMALLINT) — номер недели в году

4. Определение таблицы фактов (Fact Table)
	
	fact_sales (Таблица фактов продаж):
	Центральная таблица фактов, хранящая количественные и финансовые метрики событий продаж
	sales_sk (BIGINT, Primary Key) — суррогатный ключ записи о продаже
	sales_id (INT) — бизнес-ключ чека
	date_sk (INT, FK -> dim_date) — дата покупки
	client_sk (BIGINT, FK -> dim_client) — клиент, покупатель
	ticket_type_sk (BIGINT, FK -> dim_season_ticket_type) — купленный абонемент
	quantity (INT) — количество проданных единиц
	amount_paid (DECIMAL) — фактическая сумма оплаты

5. Физическая модель (Star Schema)
	Для физического моделирования выбрана схема «Звезда» (Star Schema). Таблицы измерений напрямую связываются с центральной таблицей 	фактов fact sales через внешние ключи (1 : N)
	Бизнес-ключи (client_id, ticket_type_id, sales_id)	
	Суррогатные ключи (client_sk, ticket_type_sk, date_sk, sales_sk)

6. Аналитические SQL-запросы которые помогут ответить на ключевые вопросы вашего бизнес-процесса
	
	Какова динамика проданных абонементов и общей выручки клуба по месяцам и годам?
	Какие категории и названия абонементов приносят фитнес-клубу наибольший доход?
	Клиенты какого пола и возраста генерируют основной объем выручки клуба?

7. DDL-скрипт создания структуры DWH (PostgreSQL)
	-- 1. Измерение "Клиент"
CREATE TABLE dim_client (
    client_sk BIGSERIAL PRIMARY KEY,     
    client_id INT NOT NULL,           
    full_name VARCHAR(150) NOT NULL,  
    gender    VARCHAR(10),             
    age       SMALLINT                
);

	-- 2. Измерение "Тип абонемента"
CREATE TABLE dim_season_ticket_type (
    ticket_type_sk   BIGSERIAL PRIMARY KEY,   
    ticket_type_id   INT NOT NULL,         
    name_ticket_type VARCHAR(100) NOT NULL,  
    category         VARCHAR(50) NOT NULL    
);

	-- 3. Измерение "Дата"
CREATE TABLE dim_date (
    date_sk   INT PRIMARY KEY,               
    full_date DATE NOT NULL UNIQUE,         
    day       SMALLINT NOT NULL,            
    month     SMALLINT NOT NULL,             
    year      SMALLINT NOT NULL,             
    week      SMALLINT NOT NULL              
);

	-- 4. Таблица фактов "Продажи абонементов"
CREATE TABLE fact_sales (
    sales_sk       BIGSERIAL PRIMARY KEY,                               
    sales_id       INT NOT NULL,                                     
    date_sk        INT NOT NULL REFERENCES dim_date(date_sk),        
    client_sk      BIGINT NOT NULL REFERENCES dim_client(client_sk),    
    ticket_type_sk BIGINT NOT NULL REFERENCES dim_season_ticket_type(ticket_type_sk), 
    quantity       INT NOT NULL DEFAULT 1,                           
    amount_paid    DECIMAL(10, 2) NOT NULL                           
);
